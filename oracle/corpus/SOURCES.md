Files from the Localization OS tree (its `sample-docs` folder and the hand-written PPTX and XLSX generators in its
test fixtures) are used by `python run.py --external` and read in place. Localization OS is open source under
Apache-2.0, so format crates may port its test cases and fixture files into their own `tests/data` folders.

Apart from the Okapi test resources listed above (Apache-2.0, unmodified, attributed per file), nothing was copied from Okapi or any other third-party test set. The LocOS parity corpus mentioned in the brief is
not present in the LocOS tree on this machine.

| `sdlppx/trados_demo.sdlppx`, `sdlppx/trados_ja.sdlppx` | `gen_packages.py`. A Trados project package: a `PackageProject` `.sdlproj` manifest (one language direction), one target SDLXLIFF (de-DE with tags, a locked and an approved segment; ja-JP), and for the first a source file placeholder and a report. Unit ids equal the segment ids (1, 2, ...): Trados writes GUID unit ids, which Bilingua keeps apart from the segment ids in paragraph mode, and the facade contract test requires them equal, so that real shape is a finding for the lead, not a fixture. One target per package on purpose: LocOS opens a package with several targets only through its project upload. Invented text | Apache-2.0, same as Bilingua |
