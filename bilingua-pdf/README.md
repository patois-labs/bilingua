# bilingua-pdf

PDF text layer filter for Bilingua. Spec and baseline: the Localization OS filter `app/filters/pdf_filter.py` and
its suite `tests/verify_pdf.py`; Okapi `okf_pdf` for extraction only.

```rust
use bilingua_model::*;
use bilingua_pdf::Pdf;

let doc = Pdf.extract(&bytes, &ExtractOptions::new().with_target_lang("fr-FR"))?;
for w in &doc.warnings { /* "pdf_ocr_page", part "page N": a scanned page for the caller's OCR */ }
let same = Pdf.merge(&doc)?; // untouched: the original bytes
```

## What it does

- Opens the file as PDFium does: header in the first KB, cross references from `startxref` (tables, streams,
  hybrid files, `/Prev` chains, followed once even when they loop), object streams, and when that fails or the
  catalog does not load, a scan of the whole file for objects and trailers (truncated and damaged files read when
  PDFium reads them, refused when it refuses them). Flate, LZW (with PNG and TIFF predictors), ASCII85, ASCIIHex,
  RunLength. The standard security handler with an empty user password (RC4 40 and 128, AES-128, AES-256 R5 and R6);
  a file that needs a password is `Error::Unsupported`.
- Reads every page's text exactly as PDFium's `FPDFText_GetText` returns it (the text LocOS splits): a Rust port of
  `CPDF_TextPage` (line grouping, left-to-right sorting, generated spaces from gaps and kerning, `\r\n` line
  breaks, a line-end hyphen turned into U+FFFE, bidi runs reordered, fake-bold duplicates dropped, `/ActualText`),
  in float arithmetic as PDFium computes it. Fonts: ToUnicode maps, simple-font encodings and Differences through
  the Adobe glyph list, the core 14 metrics, Type 0 fonts with Identity and the predefined Unicode and legacy CJK
  CMaps (Shift-JIS, EUC-JP, GBK, Big5, EUC-KR, UHC through `encoding_rs`), embedded CMaps, Type 3 fonts, and glyph
  boxes from the embedded TrueType and CFF programs (PDFium measures text objects with them).
- Units are LocOS's: per page, the stripped text split on blank lines, lines joined with one space, one unit per
  paragraph, no inline codes. Ids `p<page>u<n>`; `context.kind` `paragraph`, `context.extra["page"]`.
- A page with less than 20 characters of stripped text is a scanned page: no units, a `pdf_ocr_page` warning. OCR
  stays in Localization OS. `page_texts()` gives every page's size, OCR flag and raw PDFium text.
- Limits: LocOS's page cap (1000), page-object cap (80 x `max_units`), OCR pixel budget, unit cap; all decoded
  streams together may unpack to `max_zip_bytes` (256 MB): a decompression bomb is `Error::Limit`.
- Merge: untouched gives the original bytes. A translated PDF is re-typeset by LocOS (typst), not here:
  `Error::Unsupported` (see `DESIGN-MERGE.md`).

`format_options`: `pdf.max_pages`, `pdf.max_stream_bytes`, `pdf.ocr_min_chars`, `pdf.ocr_max_pixel_dim`,
`pdf.ocr_max_total_pixels` (integers).

## Known differences from PDFium

- Glyph boxes of Type 1 font programs (FontFile) are not read; they are approximated from the descriptor and the
  advance, or Helvetica's metrics for a non-embedded font (PDFium uses its substitute face). Rarely changes a line
  break.
- CID to Unicode tables of the Adobe CJK collections are not included: a CJK font with no ToUnicode and Identity
  encoding gives the CID as text, where PDFium can name the character.
- TrueType `post` glyph names and the built-in encoding of symbolic TrueType programs are not read.
- On 146 real PDFs (2671 pages) two pages differ: a superscript footnote mark and a dash in a Type 1 font.

## Tests

`tests/locos_golden.rs` compares every fixture with LocOS's own result (`tests/data/locos_golden.json`, made by
`tests/tools/gen_golden.py`); `tests/locos_pdf.rs` ports `verify_pdf.py`; `tests/behaviour.rs`, `tests/hostile.rs`
(with proptest) and `tests/speed.rs`. `tests/external.rs` runs the same comparison over a folder of PDFs that are
not committed. Fixtures: `tests/tools/gen_fixtures.py` (LocOS's typst writer and hand-written PDFs).
`src/tables.rs` is generated by `tests/tools/gen_tables.py`.

## Third-party data and algorithms

- The text extraction rules follow PDFium (Copyright 2014 The PDFium Authors, BSD-3-Clause; original code copyright
  2014 Foxit Software Inc.); the code here is a new Rust implementation. `src/tables.rs` holds PDFium's encoding
  tables, bidi classes, mirror table and decomposition data.
- Adobe Glyph List (BSD-3-Clause), the CFF standard strings (Adobe TN 5176), and glyph metrics derived from Adobe's
  core 14 AFM files under Adobe's AFM notice (quoted in `src/tables.rs`).
- `flate2` (MIT or Apache-2.0) with the `zlib-rs` backend (Zlib), already in the workspace through `zip`.
